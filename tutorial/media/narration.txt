Wolai → Notion：从配置到同步
这段视频带你准备我来和 Notion 的凭证，配置同步工具，再交给 AI agent 执行。真实菜单画面已经裁切脱敏，其余步骤标注为示意。本次演示没有生成新密钥，也没有修改账号权限。

01  在 Wolai 打开个人设置
先打开我来桌面客户端。点击左上角的更多操作，选择个人设置，然后进入 MCP 接入。这里需要的是 MCP Token，不是旧开放平台的 App ID 或 App Secret。

02  创建自己的 Wolai MCP Token
在 MCP 接入页，找到创建 Token。请在你自己的账号中完成创建并安全保存。视频中的空间信息和已有密钥列表已经移除。这个项目直接连接 MCP 服务，不要求你另行配置 AI 客户端的 MCP 插件。

03  Notion：个人脚本可使用 PAT
进入 Notion 开发者门户，打开个人访问令牌，选择新建。确认工作空间，启用 Notion API 能力并选择有效期。生成后立即保存，因为完整值只会显示一次。将它填入本项目的 NOTION TOKEN 变量。

04  另一种选择：内部连接
如果使用内部连接，在开发者门户创建连接，并从配置页取得 API Token。为它启用读取、插入和更新内容能力，再在目标页面的连接菜单中添加这个连接。PAT 使用你自己的页面权限，不需要这一步。

05  指定来源与目标，不同步整个账号
接着准备两个页面 ID。在我来中选择要同步的根目录，复制页面 ID。Notion 一侧建议新建一个空的导出根页面，再取得它的页面 ID。使用 PAT 时，你本人需要有该目标页面的编辑权限。

06  在本地填写 .env
把项目里的点 env example 复制成点 env，用本地编辑器填写两项凭证。画面中的圆点不是可用密钥。不要把真实 Token 发到聊天或提交到仓库。你也可以使用系统环境变量。

07  安装依赖并初始化
在项目目录安装依赖，然后运行初始化命令，把画面里的来源和目标占位符替换成自己的页面 ID。初始化会建立私人数据目录。已有状态时应核对原配置，不要重新初始化覆盖。

08  先检查连接，再看只读计划
先执行远端连接检查，再运行不带 apply 的同步命令。它只读取来源并生成计划，不写入 Notion。确认账号、目标目录和扫描范围正确以后，再进入写入步骤。检查失败时先处理本地凭证或页面访问问题。

09  分批同步，完成后验收
范围确认后，加 apply 执行写入。正常分批未结束时，用 resume 继续；快照过期或来源变化时重新扫描。正文和目录剩余都为零、导航完成以后，再运行 verify。只有验收通过，才报告本次检查通过。

10  交给 AI agent 执行
更省事的方式，是把项目中 AI 快速使用指南的完整提示词发给 agent，填写路径和两个页面 ID。凭证在本地准备即可。agent 会依次检查、预览、分批同步和验收，出现保护冲突时保留现场。

完成前，还要看这些例外
最后确认报告里的例外。超限文件可能只保留来源链接，某些原件或整页内容会以 ZIP 保存，数据库容器不代表完整记录已经复制。视频和命令模板都在项目中，实际权限和按钮名称以你当前的客户端为准。
